# 2 — IDOR (Insecure Direct Object Reference)

**The vuln:** `GET /api/invoices/{id}` checks you're logged in, but never checks the invoice
belongs to you. The `{id}` is a number you control.

**The exploit:** log in as a normal user, then walk the id past your own.
```bash
curl -s http://<host>:5002/api/invoices/3 -H "Authorization: Bearer <token>"
# invoice 3 is the admin's — the flag is in its notes
```

**The fix:** authorize per *record*, not per route.
```csharp
var invoice = await db.Invoices.FindAsync(id);
if (invoice is null) return Results.NotFound();
if (invoice.OwnerId != currentUserId) return Results.StatusCode(403);   // not yours
```
Better still, filter in the query so a row that isn't yours never loads:
`db.Invoices.FirstOrDefault(i => i.Id == id && i.OwnerId == currentUserId)`.

**The lesson:** being authenticated is not being authorized. Check ownership on every object.
