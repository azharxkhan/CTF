# 9 — JWT validation switched off

**The vuln:** the signing key is strong, but someone turned off the claim checks to silence an
error:
```csharp
new TokenValidationParameters {
    ValidateIssuer = false, ValidateAudience = false, ValidateLifetime = false,  // the bug
    ValidateIssuerSigningKey = true, IssuerSigningKey = key
}
```
So a validly-signed token minted for a *different* issuer/audience is accepted.

**The exploit:** the partner endpoint hands out an admin token for another system.
```bash
curl http://<host>:5009/api/partner/token          # role=admin, but iss/aud = the HR system
curl http://<host>:5009/api/admin/data -H "Authorization: Bearer <that token>"   # accepted → flag
```

**The fix:** turn the validations back on and pin the values.
```csharp
ValidateIssuer = true,  ValidIssuer = "acme-api",
ValidateAudience = true, ValidAudience = "acme-clients",
ValidateLifetime = true, ClockSkew = TimeSpan.FromMinutes(1),
```

**The lesson:** the defaults are secure. The bug is disabling them. `alg:none` is a red
herring — ASP.NET rejects it by default.
