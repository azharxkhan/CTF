# 12 — API key in the JS bundle

**The vuln:** the admin dashboard ships an over-privileged API key inside its client-side
JavaScript. Anything sent to the browser is public.

**The exploit:** read the key from the bundle, then use it on a privileged endpoint.
```bash
curl -s http://<host>:5012/dashboard/app.js | grep API_KEY   # const API_KEY = "ak_live_…"
curl -s http://<host>:5012/api/admin/export -H "X-Api-Key: ak_live_…"   # flag
```

**The fix:**
- Don't put privileged keys in client code — the browser gets, at most, a token scoped to
  exactly what that user may do.
- Proxy privileged calls through your backend, authenticated as the user (session cookie); the
  admin/platform key lives only server-side.
- Scope any client-visible key to the minimum, and rotate the leaked one immediately.

**The lesson:** client-side is public. You cannot hide a secret in JavaScript — obfuscation is
not a fix.
