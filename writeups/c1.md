# 1 — SQL injection (string concatenation)

**The vuln:** the product search builds SQL by concatenating your input into the query text:
```csharp
var sql = "SELECT Sku, Name, Category, Price FROM Products WHERE Name LIKE '%" + q + "%'";
```
Your input becomes *code*, not just data.

**The exploit:** close the quote, comment the tail, and UNION in another table.
```
q = ' OR 1=1 --                                     → every product (injectable)
q = ' UNION SELECT NULL, Secret, NULL, NULL FROM Flags --   → the flag
```
Match the column count (4) and put the secret in a text column.

**The fix:** parameterize — the query text is constant; the value is a bound parameter.
```csharp
var sql = "SELECT Sku, Name, Category, Price FROM Products WHERE Name LIKE @name";
cmd.Parameters.AddWithValue("@name", "%" + q + "%");   // q is data, never SQL
// or EF: context.Products.Where(p => p.Name.Contains(q))
```

**The lesson:** never build SQL with string concatenation. Parameterize every query.
